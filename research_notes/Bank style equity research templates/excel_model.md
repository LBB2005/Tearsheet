# Bank-quality equity Excel workbooks: layout, formatting, modelling standards, auditing, and Python generation

Scope note: these notes cover (a) a "numbers" workbook that presents a research report's figures and (b) a small, accurate valuation model with editable inputs, both generated with Python (openpyxl or XlsxWriter) from stored report data (rating, 12-month bear/base/bull range, DCF / residual income / multiples blended into an estimated value, factor percentiles vs peers, key metrics, returns, peers, cited sources).

Source quality: the ICAEW Financial Modelling Code (2024 edition) was read in full and is the strongest primary source here. Bank-training sources (Wall Street Prep, Financial Edge) were read directly but cover colour coding only briefly. Several formatting specifics come from secondary interview-prep or practitioner blogs, and those are flagged. The FAST Standard site, the SMART guidance, BIWS and Training The Street pages could not be fetched (certificate errors or 403s), so those standards are covered only through secondary sources. Library behaviour (openpyxl, XlsxWriter, `formulas`, LibreOffice) was checked by running code in this session, and the versions used are given for each result.

## Tab layout and order (cover/README, summary, inputs, historicals, projections, valuation, sensitivity, checks, sources); what sell-side models contain

### Takeaway
Standards agree that logic should run inputs → calculations → outputs, left to right and top to bottom like a book. They also call for a contents/navigation sheet, a user-guide sheet, a dashboard of key outputs, a check summary, and no hidden sheets. No public source gives a single canonical sell-side tab list. Sell-side models handed to clients (as aggregated by Visible Alpha) are full working earnings models with line items down to segment and product level, plus industry KPIs.

### Cited Findings
- ICAEW Code, "Plan and assess the workbook layout": "Logic should also flow consistently from inputs to calculations to outputs." It also says to "Segregate inputs (assumptions), calculations and outputs (results), either by using separate worksheets, or demarcated sections on the same worksheet." — [ICAEW Financial Modelling Code (© ICAEW 2024, 08/24)](https://www.icaew.com/-/media/corporate/files/technical/technology/excel-community/financial-modelling-code.ashx)
- ICAEW Code: "Set up your model to read like a book: with logic flowing from top to bottom within each worksheet, and from left to right both within each worksheet and across sheets within a workbook," and "Display time periods horizontally." — [ICAEW Code](https://www.icaew.com/-/media/corporate/files/technical/technology/excel-community/financial-modelling-code.ashx)
- ICAEW Code recommends that you "Include one or more dashboards summarising important outputs that answer the questions the model was built for." Dashboards may hold key inputs only if those inputs are "very clearly identified." — [ICAEW Code](https://www.icaew.com/-/media/corporate/files/technical/technology/excel-community/financial-modelling-code.ashx)
- ICAEW Code on navigation: "Include an intuitive directory and navigation system, including such elements as a table of contents, a diagram of the model's logic flow and clickable hyperlinks." — [ICAEW Code](https://www.icaew.com/-/media/corporate/files/technical/technology/excel-community/financial-modelling-code.ashx)
- ICAEW Code on guidance: "Include in the model a worksheet dedicated to being a user guide." Also: "Don't store documentation in a separate file or email that may become separated from the model itself." User guidance should state key calculation assumptions (example: "all cash flows occur at the end of the appropriate period"). — [ICAEW Code](https://www.icaew.com/-/media/corporate/files/technical/technology/excel-community/financial-modelling-code.ashx)
- ICAEW Code on hiding: "Don't use hidden worksheets," "Don't hide intermediate calculations," and "Don't hide items using white text colour." The only exception allowed is hiding empty columns and rows beyond the used range. Grouping and collapsing rows and columns is acceptable. — [ICAEW Code](https://www.icaew.com/-/media/corporate/files/technical/technology/excel-community/financial-modelling-code.ashx)
- ICAEW Code on actuals and forecasts: "Create separate entry areas for forecast and actual numbers, with formulas that select which data is currently in use." Also: "Don't overwrite forecast data with actuals on a rolling basis." — [ICAEW Code](https://www.icaew.com/-/media/corporate/files/technical/technology/excel-community/financial-modelling-code.ashx)
- ICAEW Code on sheet naming: use clear names, not Sheet1 or Sheet2. "Colour-code or label worksheets according to their functional purpose… For example, include yellow fill and/or an I_ prefix for input worksheets." Also: "Don't use mathematical operators in worksheet names." — [ICAEW Code](https://www.icaew.com/-/media/corporate/files/technical/technology/excel-community/financial-modelling-code.ashx)
- ICAEW Code recommends a "dedicated check summary section (this may be a standalone worksheet or a section within a worksheet)." — [ICAEW Code](https://www.icaew.com/-/media/corporate/files/technical/technology/excel-community/financial-modelling-code.ashx)
- An IB interview-prep guide recommends a hyperlinked table-of-contents tab for models with 30+ tabs. It also recommends logging a version history (date, analyst, key changes) on the cover tab or a dedicated tab. — [ibinterviewquestions.com formatting guide](https://ibinterviewquestions.com/guides/valuation-investment-banking/formatting-standards-color-conventions-ib-models) (secondary source)
- Visible Alpha (S&P Global) "obtains raw sell-side models – not reports." It extracts "data and forecasts from each analyst, down to segment and product-level assumptions." Its pre-standardised line items cover financial line items, operating metrics and industry KPIs, and per one vendor page it works with "over 250 sell-side firms, who contribute their full working models." These are vendor marketing pages with self-reported figures. — [Visible Alpha Insights for Equity Research Analysts](https://visiblealpha.com/?p=5522); [S&P Global Visible Alpha Insights](https://www.spglobal.com/market-intelligence/en/solutions/visible-alpha-insights)
- John Moschella's *Financial Modeling for Equity Research* (written by a former sell-side research associate) centres on earnings modelling, i.e. building the P&L forecast. Only the book listing was found, not its contents. — [book listing](https://www.bookexpress.nz/products/financial-modeling-for-equity-research-a-step-by-step-guide-to-earnings-modeling-by-john-moschella-cfa-cpa-john-moschella-cfa-cpa-509x)

### Inferences
- Recommended tab order for the Tearsheet workbook, designed from the ICAEW rules above. This is a proposal, not a documented bank standard:
  1. `Cover`: company, ticker, exchange, currency, report date, data as-of date, rating, 12-month bear/base/bull values and current price. Also a colour/format key (ICAEW: "Include a formatting key"), a hyperlinked table of contents, a short user guide, the master-check status and a short disclaimer.
  2. `Summary`: dashboard of outputs (estimated value, upside/downside versus price, blend weights, bear/base/bull, key metrics). Output only, no inputs, or clearly flagged ones.
  3. `Inputs`: every editable assumption in one place, including the scenario selector, WACC build, growth, margins, capex, terminal growth or exit multiple, target multiples and method weights. Each row carries a label, units, value(s) and a source ID. Give the tab a yellow tab colour, per ICAEW's "yellow fill… for input worksheets".
  4. `Historicals`: reported FY…A figures as blue hard-codes with a source column. These are kept separate from forecasts, per ICAEW's separate actual and forecast areas.
  5. `Forecast`: FY…E projections, all formulas.
  6. `DCF`, 7. `ResidualIncome`, 8. `Multiples`: one valuation method per sheet.
  9. `Valuation`: blend of methods → estimated value per share, plus the bear/base/bull outputs.
  10. `Sensitivity`: WACC × terminal growth grid, plus optional exit-multiple and margin grids.
  11. `Peers`: peer multiples and metrics, plus factor percentiles versus peers. This is a "numbers" presentation tab, mostly hard-codes.
  12. `Returns`: price and total returns versus benchmark (a data tab).
  13. `Checks`: every tie-out and integrity check, plus the master check.
  14. `Sources`: numbered list of cited sources (ID, title, publisher, date, URL, accessed date), which the source-ID columns in other tabs point to.
  15. `Notes`: methodology notes, definitions, sign convention, units and full disclaimer. It could be merged into Cover for brevity.
- For a "numbers only" companion (figures as published, no live model), the same Cover/Sources/Notes shell can wrap pure data tabs (Summary, KeyMetrics, Valuation, Peers, Factors, Returns), with every number hard-coded in blue and sourced.
- Sell-side distributed models are earnings models with many line items (quarterly and annual P&L, segment builds, KPIs, balance sheet, cash flow, valuation). A Tearsheet workbook built from a report's stored outputs will be much smaller. It should say so on the Cover ("summary valuation model, not a full three-statement model") so it is not taken for a full broker model.

## Formatting conventions: colours, input shading, number formats, units, FY headers, freeze panes, gridlines, column widths, fonts, bands

### Takeaway
The near-universal convention is blue font for hard-coded inputs and historicals, black for formulas, and green for links to other sheets. External-file links are purple or red depending on firm, and red is also used for errors and flags. ICAEW adds that inputs must also be marked by fill and/or border, not by font colour alone. The usual fill is light yellow, though Macabacus suggests blue. Common number conventions are millions with one decimal, negatives in parentheses, percentages to one decimal and multiples as "12.3x". The exact hex codes most often cited are 0000FF (blue), 008000 (green) and FF0000 (red). Font family and size conventions (Arial or Calibri 10pt) were not confirmed by any source found.

### Cited Findings
- Financial Edge (bank training firm): "Historical numbers, or any hardcoded numbers, are colored blue." "Assumptions (which are hardcodes that could change) are blue with a colored background," and "different models use a variety of background colors." "Formulas or any calculation are colored black." "Formulas that link to other sheets are sometimes colored green (if not, they are black)." It also says historical numbers should be sourced and easy to tie to a source document. — [Financial Edge: Financial Model Formatting – Numbers](https://www.fe.training/free-resources/financial-modeling/financial-model-formatting-numbers/)
- Wall Street Prep: hard-coded historical inputs use "blue text in the cells and yellow shading in the background," and formulas use "black text font and a clear background." Its examples show negatives in parentheses, e.g. "($500)". — [Wall Street Prep: Financial Modeling Techniques](https://www.wallstreetprep.com/knowledge/financial-modeling-techniques/)
- ICAEW Code: "Distinguish input cells from other cell types using a defined cell fill colour and/or a cell border, not just a defined font colour." Also "Don't identify input cells solely by text-based tag or label," "Use Excel Styles to apply consistent formatting," "Include a formatting key in the model," "Don't add formats ad hoc," and "Don't leave all cells in the Excel default format." — [ICAEW Code](https://www.icaew.com/-/media/corporate/files/technical/technology/excel-community/financial-modelling-code.ashx)
- ICAEW Code on precision: the commonest formatting mistake "is to show too many decimal places," which can "overstate the level of precision." Apply conditional formatting "in modest quantities," since heavy use causes performance issues. — [ICAEW Code](https://www.icaew.com/-/media/corporate/files/technical/technology/excel-community/financial-modelling-code.ashx)
- ICAEW Code on units: label every value with its units, covering currency (real or nominal), factors ("tens, hundreds, thousands and millions") and rates ("whether they are annual or matching model periods"). Also: "Use a specified base unit, and label all values that use alternative units." — [ICAEW Code](https://www.icaew.com/-/media/corporate/files/technical/technology/excel-community/financial-modelling-code.ashx)
- ICAEW Code on panes and labels: "Use frozen panes to help orient the user and keep key labelling in view," "Label each row to the left in a frozen pane," and "Display the primary timeline in a frozen pane." — [ICAEW Code](https://www.icaew.com/-/media/corporate/files/technical/technology/excel-community/financial-modelling-code.ashx)
- ICAEW Code on signs: "Specify and use a simple and comprehensive sign convention." The two options are natural signs (revenues and inflows positive, expenses and outflows negative) or "normally positive". Also "Label each row with its convention" and "Don't use pure accounting convention (ie, positive for debits and negative for credits)." — [ICAEW Code](https://www.icaew.com/-/media/corporate/files/technical/technology/excel-community/financial-modelling-code.ashx)
- IB interview-prep guide (secondary source): blue font for hard-codes and historicals ("any value typed directly into a cell"); black for same-sheet formulas and projections; green for formulas referencing another sheet; purple for links to external files ("some banks only"); red font or fill for errors, items needing attention or placeholders; light grey fill for header rows or input sections, avoiding heavy fills. — [ibinterviewquestions.com](https://ibinterviewquestions.com/guides/valuation-investment-banking/formatting-standards-color-conventions-ib-models)
- The same guide on numbers: dollar amounts "in millions with one decimal place" (e.g. $1,234.5), with the unit in the header row; percentages to one decimal (25.3%); multiples to one decimal followed by "x" (11.2x), never "times" or a bare number; share counts in millions to one decimal; negatives "Use parentheses, not minus signs". Bold major lines (Revenue, EBITDA, EBIT, Net Income, FCF) and totals, indent sub-items, single border above subtotals, double border above grand totals. — [ibinterviewquestions.com](https://ibinterviewquestions.com/guides/valuation-investment-banking/formatting-standards-color-conventions-ib-models)
- Hex/RGB values from search snippets of secondary guides (pages not fetched, so attribution between them is uncertain): Blue = RGB 0,0,255 (0000FF) for hard-coded inputs; Green = RGB 0,128,0 (008000) for links to other worksheets; one guide uses Red RGB 255,0,0 for external links to other files, another uses purple. — [modelmint colour-coding guide](https://modelmint.pages.dev/guides/how-to-color-code-a-financial-model.html); [code-abyss financial-model standards](https://cdn.jsdelivr.net/npm/code-abyss@4.10.0/skills/analyzing-spreadsheets/references/financial-model.md)
- Practitioner blog (Alexander Jarvis): "I make every assumption a yellow box with blue text." Dropdown cells get an orange background. Headers use shades of one colour, darkest at the top level. — [alexanderjarvis.com formatting guide](https://www.alexanderjarvis.com/excel-financial-model-formatting-guide/)
- Conflicting view, Macabacus (Excel add-in vendor for bankers): suggests blue *shading* for input cells, gray or black for hard-coded numbers, orange, purple or pink for calculations, a muted grey fill for section headers, and a 6–8 colour palette avoiding neons and red–green pairings. This departs from the bank-training convention above. — [Macabacus blog](https://macabacus.com/blog/improving-model-readability-with-color-formatting)
- Multiples: the custom format `0.0x` keeps the cell numeric while showing the "x" (no quotes needed). Typing "10.0x" as text breaks calculations. — [search summary of Training The Street "Custom Number Formatting in Excel"](https://trainingthestreet.com/resources/custom-number-formatting-in-excel/) (page returned 403; only the snippet was seen). Verified locally: openpyxl 3.1.5 stores and reads back `0.0x` unchanged. A LibreOffice 26.8 round-trip rewrote it as `0.0\x`, which displays the same. — [openpyxl docs](https://openpyxl.readthedocs.io/en/stable/)
- ICAEW Excel Community published a 2026 article on number formats that show zero as a dash. Only the title was seen, not the content. — [ICAEW: Number formats again – making a dash for it](https://www.icaew.com/technical/technology/excel-community/excel-community-articles/2026/number-formats-again-making-a-dash-for-it)

### Inferences
- A concrete style sheet for generation. Hex values follow the cited convention. Fonts, sizes, widths and fills are my estimates of common practice, not sourced:

| Style | Font colour (openpyxl ARGB) | Fill | Use |
|---|---|---|---|
| Input (editable assumption) | `FF0000FF` blue | light yellow `FFFFF2CC` (estimate) + thin border | Inputs tab, scenario cells |
| Hard-coded data (historicals, peer data, stored report figures) | `FF0000FF` blue | none | Historicals, Peers, Returns |
| Formula, same sheet | `FF000000` black | none | Forecast, valuation |
| Link to another sheet | `FF008000` green | none | "Call-up" rows that import from Inputs/Historicals |
| External link | purple `FF7030A0` or red (firm-specific) | — | Avoid entirely (see ICAEW) |
| Check cell | black; conditional format red fill `FFFFC7CE` / font `FF9C0006` when ≠ 0, green `FFC6EFCE` / `FF006100` when OK | — | Checks tab and the master-check banner |
| Header band | white bold on dark navy (e.g. `FF1F3864`), estimate | dark | Section titles |
| Sub-header / units row | grey italic `FF595959` | light grey `FFF2F2F2` | "($ in millions, except per share)" |

- Number formats (standard Excel custom-format syntax, applied with `cell.number_format`):
  - Currency and amounts in millions, 1dp, negatives in parentheses, zero as dash: `#,##0.0_);(#,##0.0);"–"_)`. The `_)` pads positives by the width of ")" so columns align.
  - Per-share values: `$#,##0.00_);($#,##0.00)`, or without the `$` when the currency is in the label.
  - Percent, 1dp: `0.0%_);(0.0%);"–"_)`.
  - Multiples: `0.0x` (verified), or with negatives `0.0x_);(0.0x)` (a search-tool inference; untested).
  - Basis points: `0" bps"`.
  - Fiscal-year headers: either text strings "FY2024A" / "FY2025E", or numeric years with format `"FY"0"A"` / `"FY"0"E"` so that year arithmetic and lookups still work.
  - Store values already in the stated unit (millions) rather than scaling with the `#,##0.0,,` format. ICAEW's "clear units" principle favours an explicit units label, and storing in millions keeps the label and the stored values consistent.
- Layout estimates (common practice, unsourced): gridlines off (`ws.sheet_view.showGridLines = False`) on every presentation tab; freeze panes below the timeline header and right of the label/units columns (e.g. `ws.freeze_panes = "E6"`). Column widths: A ≈ 2 (spacer), B ≈ 40 (labels), C ≈ 10 (units), D ≈ 10 (source ID), then ≈ 11 per period column. One font throughout (Arial 10 or Calibri 10/11). Bold totals with a top border, and a double bottom border on the final value per share.
- For openpyxl, give colours in full 8-digit ARGB (`FF0000FF`) so alpha is explicit. Passing `FF0000FF` round-tripped unchanged in a local test.

## Modelling standards: FAST, SMART, ICAEW Code, bank training (one formula per row, no hard-codes in formulas, left-to-right flow, checks, named ranges, circularity)

### Takeaway
The ICAEW Code (built from seven methodologies, FAST among them, and a dozen modelling firms) gives the consensus rules. Use strictly consistent formulas across a row with anchoring for variations. Keep constants out of formulas. Use local "call-ups" instead of cross-sheet references inside calculations. Avoid array formulas, hidden items and circularity (disable iterative calculation and resolve algebraically). Include checks with a tolerance and a master check. Named ranges are optional, but if used they must be meaningful. Bank training adds blue/black/green colours and one formula per row, and tolerates a switched circularity for interest. A simple equity valuation model has no need for one.

### Cited Findings
- ICAEW Code: "Make formulas strictly consistent across formula blocks, so the formula can be copied and pasted across the block," and "Use cell anchoring to create any variations that may be required." "Very occasionally the first cell in a timeline may be different… when clearly marked," and any inconsistency must be made "immediately apparent". — [ICAEW Code](https://www.icaew.com/-/media/corporate/files/technical/technology/excel-community/financial-modelling-code.ashx)
- ICAEW Code on timelines: "Include only one timeline on each worksheet." "Don't create timelines… that do not line up across worksheets," and "Don't use 'variegated' timelines… interrupted by periodic subtotals." — [ICAEW Code](https://www.icaew.com/-/media/corporate/files/technical/technology/excel-community/financial-modelling-code.ashx)
- ICAEW Code on hard-coding: defined as "Fixed values embedded into a formula, such as a tax rate entered as 20% within a formula." "Include as inputs all values that could possibly change in the lifetime of the model." Obvious constants (24 hours, months in a year) are acceptable, but "Don't hardcode constants into formulas" whose meaning isn't obvious. Use a constants sheet instead. Don't create separate inputs for 1 and 0. — [ICAEW Code](https://www.icaew.com/-/media/corporate/files/technical/technology/excel-community/financial-modelling-code.ashx)
- ICAEW Code on calculation technique: "Break complex calculations into multiple stages," "Split multi-stage calculations across multiple rows," and use 1/0 flags for timing logic. Use "single-step references that create local references ('call ups' or 'imports')." Discouraged: "Don't include cross-sheet references within calculations," "Don't use array formulas," "Don't create unnecessary chains of references," and "Don't leave calculations set to manual." Reference nearby cells so the formula, result and inputs fit on one screen. — [ICAEW Code](https://www.icaew.com/-/media/corporate/files/technical/technology/excel-community/financial-modelling-code.ashx)
- ICAEW Code on input integrity: "Create a unique location for each input value." Where allocations must sum to 100%, the last one should be computed from the others. — [ICAEW Code](https://www.icaew.com/-/media/corporate/files/technical/technology/excel-community/financial-modelling-code.ashx)
- ICAEW Code on circularity: "Disable the 'Enable iterative calculations' setting," "Resolve circularities with logic (eg, algebraically)," and "Make simplifying assumptions to avoid circular logic." If self-reference is unavoidable, use Goal Seek or a copy-paste macro with an alert. — [ICAEW Code](https://www.icaew.com/-/media/corporate/files/technical/technology/excel-community/financial-modelling-code.ashx)
- ICAEW Code on rounding: "Round numbers only through presentation" (number formats). "Don't use the 'Precision as displayed' setting," and don't make balancing plugs for rounding. — [ICAEW Code](https://www.icaew.com/-/media/corporate/files/technical/technology/excel-community/financial-modelling-code.ashx)
- ICAEW Code on names: range names are optional ("some model developers look to minimise the use of range names… Either approach can be effective"). If used, make them meaningful ("SnrIntRate1, not SNR1"). "Don't use user-defined functions within the cells of the workbook." "Use native Excel functionality, not VBA, to perform all calculations that affect results." — [ICAEW Code](https://www.icaew.com/-/media/corporate/files/technical/technology/excel-community/financial-modelling-code.ashx)
- ICAEW Code on its status: it is "not intended to be a tick-box compliance tool". It was "formed from a review of seven methodologies and input from over a dozen financial modelling organisations." Contributors include Operis, Modano, KPMG, Grant Thornton, Mazars and RSM. — [ICAEW Code](https://www.icaew.com/-/media/corporate/files/technical/technology/excel-community/financial-modelling-code.ashx)
- Wall Street Prep handles the interest circularity in three-statement models by enabling iterative calculation (100 iterations), with a 1/0 circuit-breaker input that zeros interest to flush errors. — [Wall Street Prep](https://www.wallstreetprep.com/knowledge/financial-modeling-techniques/). This conflicts with ICAEW's "disable iterative calculations" ([ICAEW Code](https://www.icaew.com/-/media/corporate/files/technical/technology/excel-community/financial-modelling-code.ashx)).
- The PwC Global Financial Modelling Guidelines recommend one unique formula per row, copied across (seen as a search snippet only). — [PwC guidelines booklet](https://www.pwc.com.au/deals/assets/pwc-global-financial-modeling-guidelines-booklet-live.pdf). Operis frames the same idea as "left to right consistency", one of its "10 rules of financial modelling". — [Operis](https://www.operis.com/no-7-of-10-rules-of-financial-modelling-left-to-right-consistency/)
- The FAST Standard is described as a living document "organised around a set of rules" with listed exceptions (version FAST02a seen on Scribd). Secondary summaries say it separates inputs, calculations and outputs, and never hard-codes inputs into calculations. — [FAST Standard 02a copy (Scribd)](https://www.scribd.com/document/344337469/FASTStandard-02a-pdf); [Treasurers wiki: FAST Modelling Standard](https://wiki.treasurers.org/wiki/FAST_Modelling_Standard) (its certificate had expired, so not read)
- An IB guide says to choose one sign convention (all-positive costs subtracted in formulas, or natural signs) and document it. It also bans hard-coded values inside formula cells ("Every input flows from the assumptions tab") and uses Excel comments for data sources. — [ibinterviewquestions.com](https://ibinterviewquestions.com/guides/valuation-investment-banking/formatting-standards-color-conventions-ib-models)

### Inferences
- Generator rules that follow from the above:
  - (1) Each forecast row is one formula string, written programmatically with the column letter substituted, so consistency holds by construction.
  - (2) Each sheet starts with a block of green "call-up" rows (e.g. `=Inputs!F12`), so calculation rows reference only same-sheet cells.
  - (3) No numeric literals in formulas except 0, 1 and obvious period constants. Tax rate, growth, WACC, terminal growth and weights all live on `Inputs`.
  - (4) No array formulas, VBA or UDFs. No hidden sheets; use row grouping for detail instead.
  - (5) No circularity. A simple equity model avoids the interest–cash loop by taking net debt as a stated input or the last reported balance.
  - (6) Use defined names only for a few scalar inputs that appear in many formulas (e.g. `WACC`, `TerminalGrowth`, `SharesDiluted`), or none at all. Both approaches are ICAEW-compliant.
- Use the natural-sign convention (revenues and inflows positive, costs, capex and outflows negative) labelled in the units column. FCF can then be a plain `SUM`, which suits programmatic formulas.

- No source was found for Corality's SMART guidance; it may no longer be published online since Corality was acquired.

## Accuracy and auditing: tie-outs to filings, check rows that reproduce stored figures, "check = 0", documenting the source of each input

### Takeaway
Professional practice uses visible equality checks with a tolerance, conditionally formatted, rolled into a master check that shows on every sheet. Historicals should be sourced and tie back to the filing. Input sources are documented in place, via comments or a source column, never in a separate file. For a generated workbook, the natural pattern is a Checks tab where each row is (model-computed value − stored report value), which should be 0 within tolerance.

### Cited Findings
- ICAEW Code: "Include an equality check for each set of values that are calculated separately but ought to be equal, such as a balance worksheet check or an alert that a required input has been left blank." "Include a tolerance in checks to allow for very small acceptable variations, such as Excel rounding errors." "Apply conditional formatting to checks." — [ICAEW Code](https://www.icaew.com/-/media/corporate/files/technical/technology/excel-community/financial-modelling-code.ashx)
- ICAEW Code: "A master check tests whether any checks in the model are in breach and alerts the user." "Display the result of the master check in the frozen pane on all worksheets." It also distinguishes "alerts" for business issues (e.g. covenant breach or losses) from error checks. — [ICAEW Code](https://www.icaew.com/-/media/corporate/files/technical/technology/excel-community/financial-modelling-code.ashx)
- ICAEW Code on testing: "Create expectations as to how a model's results should vary with changes in inputs, apply these input changes to the model and compare the outputs with the expectations." Peer review is recommended for significant models. — [ICAEW Code](https://www.icaew.com/-/media/corporate/files/technical/technology/excel-community/financial-modelling-code.ashx)
- ICAEW Code on restrictions: "Use data validation to reduce the chance of invalid data being entered… or with dropdown menus." "Don't use data validation with a generic error message and no guidance." "Protect sensitive worksheets or ranges with a password." — [ICAEW Code](https://www.icaew.com/-/media/corporate/files/technical/technology/excel-community/financial-modelling-code.ashx)
- Financial Edge: historical numbers "should be sourced and easy to tie to a source document." — [Financial Edge](https://www.fe.training/free-resources/financial-modeling/financial-model-formatting-numbers/)
- IB guide: "Use Excel comments for non-obvious formulas and data sources." — [ibinterviewquestions.com](https://ibinterviewquestions.com/guides/valuation-investment-banking/formatting-standards-color-conventions-ib-models)
- ICAEW Code: "Identify dummy data clearly with formatting or labelling." — [ICAEW Code](https://www.icaew.com/-/media/corporate/files/technical/technology/excel-community/financial-modelling-code.ashx)

### Inferences
- `Checks` tab design for the Tearsheet model. Columns: Check | Model value | Stored report value | Difference | Tolerance | Pass (1/0). Rows:
  - (a) each valuation method's value per share vs the stored figure;
  - (b) blended estimated value vs stored;
  - (c) bear/base/bull values vs stored;
  - (d) each historical line used vs stored source figure;
  - (e) method weights sum to 100%;
  - (f) WACC > terminal growth;
  - (g) bear ≤ base ≤ bull;
  - (h) no blank required inputs (`COUNTBLANK`).
- Formula pattern: `=IF(ABS(C5-D5)<=F5,1,0)`. Use a tolerance of 0.005 per share or 0.05 for $m figures, so that rounding in the stored data does not trigger false failures. Master check: `=IF(MIN(G5:G30)=1,"OK","ERROR")`. Reference it in row 1 of every sheet (e.g. `=Checks!$C$2`), with conditional red/green formatting, inside the frozen pane.
- "Model reproduces stored output" is the decisive accuracy test. Stored report values go on `Checks` (or `Historicals`) as blue hard-codes. The live model is built only from `Inputs`, and the difference must be 0 when inputs equal the report's assumptions. If the user edits inputs, the checks will (correctly) show divergence. Label these rows "Reconciles to report (only when inputs = report case)" so a divergence is not read as an error. ICAEW calls these "alerts" rather than "checks".
- Source documentation: a `Source` column next to every hard-coded row holding a short ID (e.g. `S3`) that resolves on the `Sources` tab, plus optional cell comments with the exact filing reference (e.g. "10-K FY2024, p.52, Consolidated Statements of Operations"). Hyperlinks from the source ID to the Sources row, and from the Sources URL to the filing.

- No public bank-specific documentation was found showing how sell-side teams tie their models to 10-K figures (e.g. sign-off checklists). Only general guidance (Financial Edge, ICAEW) was found.

## Simple valuation model design: minimal DCF, residual income, multiples, bear/base/bull scenarios, sensitivity tables, validating a model against a known stored output

### Takeaway
The minimal credible DCF needs revenue growth, operating margin, tax rate, D&A, capex and working-capital intensity to build unlevered FCF. That is discounted at WACC with a Gordon-growth terminal value (WACC must exceed g), with an exit multiple as a cross-check, then bridged from EV to equity per share via net debt and diluted shares. Residual income is book value plus the PV of (NI − cost of equity × opening book value). Multiples apply target multiples to forward metrics. Scenarios work best as one input block with a selector. Sensitivity grids are either Excel Data Tables (the standard, but Excel-only and slow) or explicit formula grids (portable and testable).

### Cited Findings
- Residual income: "the intrinsic value of a stock can be determined as the sum of the current book value of the company's equity and the present value of future residual incomes discounted at the relevant cost of equity." — [CFI: Residual Income Valuation](https://corporatefinanceinstitute.com/resources/valuation/residual-income-valuation)
- RI per period equals net income minus the equity charge (cost of equity × opening book value), equivalently (ROE − k) × book value. The model assumes clean-surplus accounting (book value changes only through earnings less dividends) and suits stable-ROE firms such as financials. — [search summary of CFA/CFI residual income material](https://www.cfainstitute.org/membership/professional-development/refresher-readings/residual-income-valuation); [getoncourse CFA RI strengths/weaknesses](https://getoncourse.ai/lessons/cfa/equities-level-ii/residual-income-valuation/strengths-and-weaknesses-of-residual-income-models/) (snippets, not fetched)
- DCF mid-year convention: explicit-period discount exponents of 0.5, 1.5, 2.5… Terminal value is discounted at end of the projection period, or at mid-year depending on convention. Perpetuity-growth TV only makes sense when WACC > g. — [DCF skill page summarised in search (low-quality, auto-generated source)](https://tessl.io/registry/skills/github/NousResearch/hermes-agent/dcf-model); [ibinterviewquestions DCF guide](https://ibinterviewquestions.com/guides/valuation-investment-banking/best-practices-building-dcf-model-excel)
- Sensitivity: Excel's two-variable Data Table is standard, with WACC and growth as the row/column inputs pointing at the model's input cells. Data tables are "memory intensive," so analysts often set calculation to "Automatic except tables" and press F9. — [Financial Edge: DCF – Sensitizing for Key Variables](https://dev.fe.training/?p=10001433) (snippet); conflicting advice to use plain formula grids instead of the Data Table feature — [skills.sh dcf-model](https://skills.sh/fivetaku/claude-office-skills/dcf-model) (low-quality source)
- One source suggests terminal growth for a mature US business be capped near nominal GDP growth (cited as ~2.3–2.4% per Damodaran, January 2026). This is a single secondary source and should be checked. — [search summary, DCF guide](https://ibinterviewquestions.com/guides/valuation-investment-banking/best-practices-building-dcf-model-excel)
- ICAEW Code: the builder should provide "an engine through which alternative scenarios and sensitivities can be passed." Use 1/0 flags for logic, and keep a single location per input. — [ICAEW Code](https://www.icaew.com/-/media/corporate/files/technical/technology/excel-community/financial-modelling-code.ashx)

### Inferences
- Minimal DCF layout on `DCF` (periods FY+1E…FY+5E across, columns F–J):
  - Call-ups: Revenue growth %, EBIT margin %, Tax rate %, D&A % revenue, Capex % revenue, ΔNWC % of Δrevenue.
  - Calculation rows: Revenue = prior × (1+g); EBIT = Revenue × margin; NOPAT = EBIT × (1−t); + D&A; − Capex; − ΔNWC; = UFCF; period number t; discount factor = 1/(1+WACC)^(t−0.5 if mid-year else t); PV of UFCF.
  - Below the grid: TV = UFCF_N × (1+g)/(WACC−g); PV of TV; EV = ΣPV + PV(TV); less net debt (and minorities/preferred if relevant); = Equity value; ÷ diluted shares = value per share. Also show implied exit EV/EBITDA and TV as a % of EV, a standard reasonableness check.
  - WACC build on `Inputs`: risk-free, ERP, beta → cost of equity (CAPM); pre-tax cost of debt × (1−t); weights from market cap and net debt.
- Residual income on `ResidualIncome`: opening BVPS; EPS forecast; DPS (or payout %); closing BVPS = opening + EPS − DPS (clean surplus); equity charge = k_e × opening BVPS; RI = EPS − charge; discount factor; PV(RI); terminal RI as a perpetuity with growth (or fade/persistence factor ω); value = BVPS_0 + ΣPV(RI) + PV(TV).
- Multiples on `Multiples`: one row per method (P/E × forward EPS; EV/EBITDA × forward EBITDA → less net debt ÷ shares; P/B × BVPS; P/S etc.). The target multiple is an input, with the peer median from `Peers` shown alongside for reference, as green links.
- Blend on `Valuation`: method value per share × weight (weights on Inputs and summing to 100%, enforced by a check), giving the estimated value. Upside = value / price − 1.
- Scenarios: on `Inputs`, give each driver three columns (Bear | Base | Bull) plus a "Live" column `=CHOOSE(ScenarioIdx, Bear, Base, Bull)` or `=INDEX(F12:H12, ScenarioIdx)`. ScenarioIdx comes from a data-validation dropdown ("Bear,Base,Bull") via `MATCH`. All calculations reference only the Live column.
  - Because a single live model shows one scenario at a time, show all three values at once on `Valuation`. Either store the report's bear/base/bull outputs as blue hard-codes with checks, or (heavier) replicate the compact DCF per scenario in three blocks.
- Sensitivity on `Sensitivity`: prefer explicit formula grids over Excel Data Tables for a generated, tested workbook. The WACC values go down the rows and g across the columns (e.g. ±100 bp in 50 bp steps), both computed from the live inputs.
  - Each cell computes value per share in closed form from the UFCF row, e.g. `=(SUMPRODUCT(DCF!$F$20:$J$20,1/(1+$B8)^(DCF!$F$22:$J$22-0.5))+DCF!$J$20*(1+C$7)/($B8-C$7)/(1+$B8)^DCF!$J$22-NetDebt)/Shares`.
  - This is one consistent formula across the block, it evaluates in LibreOffice, `formulas` and pycel, and the centre cell equals the base value, which gives a free check.
  - Downside: it duplicates DCF logic, which the low-quality source above warns can drift. Mitigate with a check that the centre cell equals `DCF` value per share.
- Validation against a known stored output: set Inputs to the report's base-case assumptions → recalculate (LibreOffice headless, or `formulas`/pycel) → assert each Checks difference is within tolerance. Repeat for bear and bull by switching ScenarioIdx. Run the check in the generator's test suite and fail the build on any mismatch.
- Sanity alerts: TV % of EV > 85% (estimate threshold), negative UFCF in the terminal year, g ≥ WACC, implied exit multiple outside the peer range.

### Gaps
- No primary bank or training-firm page was fetched that shows a minimal DCF tab layout cell by cell. The layout above is synthesised from standard practice.
- Whether LibreOffice and the `formulas` library correctly evaluate Excel's native Data Table (`{=TABLE(...)}`) was not tested. LibreOffice's equivalent is MULTIPLE.OPERATIONS. openpyxl does expose a `DataTableFormula` class (confirmed in openpyxl 3.1.5), but writing one was not tested.
- The mid-year terminal-value convention is disputed between sources; no authoritative text (e.g. Rosenbaum & Pearl, McKinsey *Valuation*) was consulted.

## Practical: what openpyxl can and can't do; recalculation for testing; alternatives (XlsxWriter, `formulas`, pycel)

### Takeaway
openpyxl writes formulas but never calculates them, so formula cells have no cached values until Excel or LibreOffice recalculates. Readers that don't calculate (previewers, some mobile apps, `data_only=True` loads) see blanks. XlsxWriter writes a cached value of 0 by default, or a value you supply, and flags the file for full recalculation on open. That makes "Python computes, XlsxWriter writes formula plus value" the best route to a file that looks right everywhere. For tests, LibreOffice headless conversion recalculates and fills cached values (verified), and the `formulas` library computes them in pure Python (verified).

### Cited Findings
- openpyxl `load_workbook(data_only=True)` returns "the value stored the last time Excel read the sheet" instead of the formula. openpyxl "does currently not read all possible items in an Excel file," and "shapes will be lost from existing files if they are opened and saved." — [openpyxl tutorial](https://openpyxl.readthedocs.io/en/stable/tutorial.html)
- openpyxl has a long-standing open request to keep or fill the cached value of formula cells, i.e. it does not compute them. — [openpyxl issue #578 "Allow keeping value cache with formula cells"](https://foss.heptapod.net/openpyxl/openpyxl/-/issues/578); [issue #24 "formula calculation"](https://foss.heptapod.net/openpyxl/openpyxl/-/issues/24)
- **Verified locally (openpyxl 3.1.5):** a formula `=A1*2` written by openpyxl reads back as `None` with `data_only=True`. Font colour `FF0000FF`, `number_format` `0.0x`, `showGridLines=False` and `freeze_panes="C5"` all round-trip. `ArrayFormula` and `DataTableFormula` classes exist in `openpyxl.worksheet.formula`. `"STDEV.S" in openpyxl.utils.FORMULAE` is False (newer functions need the `_xlfn.` prefix) while `"NPV"` is True. — [openpyxl docs](https://openpyxl.readthedocs.io/en/stable/)
- openpyxl data validation: `DataValidation(type="list", formula1='"Bear,Base,Bull"', allow_blank=True)` with `error`, `errorTitle`, `prompt` and `promptTitle`, then `ws.add_data_validation(dv)` and `dv.add("C5")`. Types are list, whole, decimal, date, time, textLength and custom, with `operator`, `formula1` and `formula2` (e.g. between 0 and 1). Caveats: "Validations without any cell ranges will be ignored when saving." `showDropDown=True` *hides* the arrow. — [openpyxl validation docs](https://openpyxl.readthedocs.io/en/stable/validation.html)
- openpyxl charts: `BarChart`, `Reference` and `ws.add_chart()`. Styles go through `openpyxl.styles.Font` and related classes. — [openpyxl simple usage](https://openpyxl.readthedocs.io/en/stable/usage.html)
- XlsxWriter: "XlsxWriter doesn't calculate the result of a formula and instead stores the value 0 as the formula result." It sets a flag so "all formulas and functions should be recalculated when the file is opened." An optional `value` argument (`worksheet.write_formula('A1', '=2+2', num_format, 4)`) stores a chosen cached result, including error codes. "Applications that don't have a facility to calculate formulas will only display the 0 results." Formulas must use US-English function names and comma separators. Excel 2010+ functions need the `_xlfn.` prefix (or `use_future_functions`). Use `write_dynamic_array_formula()` for spilling formulas. — [XlsxWriter: Working with Formulas](https://xlsxwriter.readthedocs.io/working_with_formulas.html)
- XlsxWriter "cannot read or modify existing Excel XLSX files." It supports formatting, images, charts, page setup, autofilters, conditional formatting and more, and its files are "in most cases… 100% equivalent to files produced by Excel." — [XlsxWriter introduction](https://xlsxwriter.readthedocs.io/introduction.html)
- **Verified locally (XlsxWriter 3.3.1):** `write_formula("A2","=A1*2")` reads back via openpyxl `data_only=True` as `0`. `write_formula("A3","=A1*3",None,15)` reads back as `15`. — [XlsxWriter docs](https://xlsxwriter.readthedocs.io/working_with_formulas.html)
- LibreOffice headless: `soffice --headless --convert-to xlsx --outdir out/ book.xlsx` reopens, recalculates and resaves, filling cached values. A heavier option uses a StarBasic macro to force a full recalculation and scan for `#REF!` / `#DIV/0!`. — [search summary of agent-skill docs on xlsx recalculation](https://instagit.com/anthropics/skills/how-do-i-work-with-excel-files-using-the-xlsx-skill) (secondary)
- **Verified locally (LibreOffice 26.8.2.2 on this Mac at `/opt/homebrew/bin/soffice`):** converting an openpyxl-written file with `soffice --headless --norestore -env:UserInstallation=file://<tmp profile> --convert-to xlsx --outdir out <file>` populated the cached values (`=A1*2` → 0.18; `=_xlfn.STDEV.S(...)` → 0.0636). Gridlines-off and freeze panes were preserved. The format `0.0x` came back as the equivalent `0.0\x`. — [LibreOffice](https://www.libreoffice.org/)
- `formulas` library: "implements an interpreter for Excel formulas" and compiles workbooks to Python, so they run without Excel. Its `ExcelModel` has `load`, `calculate`, `write`, `compare` and `solve_circular`, plus a `formulas calc` / `formulas test` CLI. Licence EUPL 1.1+. — [formulas docs](https://formulas.readthedocs.io/en/stable/)
- **Verified locally (formulas 1.3.4):** `formulas.ExcelModel().loads(path).finish().calculate()` computed `'[op.xlsx]INPUTS'!A2` = 0.18 for the openpyxl file. It emitted Python 3.12 SyntaxWarnings from its own source, which were harmless. — [formulas docs](https://formulas.readthedocs.io/en/stable/)
- pycel: "translates an Excel spreadsheet into executable Python code." API: `ExcelCompiler(filename=...)`, `.evaluate('Sheet1!D1')`, `.set_value('Sheet1!A1', 200)`, `.to_file()`. It can validate compiled calculations against values already stored in the workbook. Not every function is implemented, VBA is not compiled, and it should only be used on trusted workbooks (advisory CVE-2024-53924). — [pycel GitHub](https://github.com/dgorissen/pycel)

### Inferences
- **Recommended generation approach for Tearsheet:**
  - (1) Python already holds the authoritative numbers (stored report data), and a Python mirror of the simple valuation maths computes every formula cell's value.
  - (2) Write the workbook with **XlsxWriter**, passing each formula with `value=` set to the Python result. The file then opens correctly in Quick Look, previewers and Google Sheets import, and Excel still recalculates on open.
  - (3) openpyxl is the choice if the generator must later edit existing files or templates. In that case, run LibreOffice headless over the output before shipping, so that cached values exist.
  - Either library supports fonts, fills, borders, number formats, freeze panes, gridlines off, column widths, comments, hyperlinks, defined names, data validation, conditional formatting, charts, page setup and sheet protection. Protection and comments were not verified this session for either library; they are standard features of both.
- **Test harness:**
  - (a) Generate the workbook.
  - (b) Recalculate with LibreOffice headless into a temp dir, using a throwaway `-env:UserInstallation` profile so it does not collide with a running LibreOffice.
  - (c) Load with openpyxl `data_only=True`, assert the master check = "OK", and assert each key output cell matches the stored report value within tolerance.
  - (d) Also scan all cells for error strings (`#REF!`, `#DIV/0!`, `#NAME?`, `#VALUE!`).
  - (e) Optionally cross-check with `formulas` (pure Python, no LibreOffice dependency, good for CI). If XlsxWriter cached values are used, assert that cached values equal the LibreOffice-recalculated values, which proves the formulas and the Python mirror agree.
- Editable inputs: lock all cells and unlock only input cells (`cell.protection = Protection(locked=False)`), and protect formula sheets *without* a password (`ws.protection.sheet = True`). Users are guided but can still unprotect and audit. ICAEW suggests password-protecting sensitive ranges; for a downloadable research model, no password is friendlier. This is a judgement call.
- Avoid in generated files: functions newer than Excel 2010 unless prefixed (`_xlfn.`); dynamic arrays and `LET`/`LAMBDA` (LibreOffice and `formulas` support is uncertain); Data Tables (not portable, untested here); external links; and macros (.xlsm).
- Comments: openpyxl `Comment(text, author)` and XlsxWriter `write_comment()` can hold per-input source citations. Keep a Source-ID column as the primary mechanism, because comments are invisible when printed.

### Gaps
- Sheet protection, comments, hyperlinks and conditional formatting were not run through the LibreOffice round-trip this session. It is unconfirmed that LibreOffice conversion preserves data validation and conditional formatting exactly.
- The LibreOffice "Recalculation on File Load" setting (Never/Always/Prompt for Excel 2007+ files) and its default could not be confirmed from the help page fetched. In the local test, formula cells with no cached value were calculated on conversion regardless.
- pycel's latest release date and `formulas`' function-coverage percentage were not found.
