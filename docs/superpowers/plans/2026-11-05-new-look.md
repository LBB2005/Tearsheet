# Tearsheet's new look: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the look Liam approved into the app and the engine. That covers:

*   the native window, the Claude-style sidebar and the menus;
*   the first-time setup and the home page;
*   the look C report, with its numbers column and Summary view;
*   the chart split from the right;
*   the Glass app icon.

**Architecture:**

*   **The engine computes, the app shows.** The engine gets:
    *   a reader that turns any stored report into structured numbers;
    *   a rewritten report template;
    *   new JSON-RPC methods for the sidebar, look-up, chart series, the full-history download,
        key checks and the safety check.
*   **The app is a new React shell over the same sandboxed window.** The report stays the engine's
    HTML in an `iframe srcdoc sandbox=""`. Everything interactive (sidebar, home, setup, chart,
    divider) is app UI beside it.
*   **Work proceeds in four parts, each leaving a working app:** the engine, the shell, setup and
    home, then the report and chart.

**Tech Stack:**

*   **Engine:** Python 3.12, pydantic, Jinja2 and pytest, run with `uv`.
*   **App:** Electron, electron-vite, React 18 and TypeScript, with vitest in the `node`
    environment. There is no DOM test library, so only pure logic is unit-tested.

**Spec:** [`docs/designs/report-look.md`](../../designs/report-look.md). The prototypes it names
are the visual reference:

*   `docs/designs/report-look-c-prototype.html`
*   `docs/designs/report-look-c-chart-split.html`
*   `docs/designs/opening-and-setup.html`
*   `docs/designs/app-icon-versions.html`

Copy the class names, colours and spacing from them freely. Where the prototypes and the spec
differ, the spec wins.

## Global Constraints

*   **The report frame.** "The report stays the engine's HTML, shown in an iframe with srcdoc and
    an empty sandbox attribute, with no scripts."
*   **Text.** "All AI and source text is escaped plain text." The Jinja environment keeps
    `autoescape` on, and nothing from a report is passed through `|safe` except SVG the template
    builds itself from numbers.
*   **Security policies.** "The content-security policies stay as they are, so styles must be
    inline or in the template, with no outside fonts or scripts." Use Mac system fonts only:
    Avenir Next for the UI, SF Mono for code.
*   **App links.** "Flag and re-read links stay `tearsheet:` links handled by `navigation.ts`."
*   **The window.** "The window stays sandboxed with no Node access." Every new ability is a named
    command in the preload bridge.
*   **Keys.** Keys are never shown, logged or sent to the window after saving. They live only in
    the Keychain (`config.set_key`).
*   **Sign-in.** Sign-in status comes only from each tool's own status command, never from its
    token files.
*   **No commands on the user's behalf.** Nothing runs a command for the user. Open Terminal only
    opens Terminal. The one-click install is built but switched off; it stays off until Anthropic
    approves it.
*   **Look.** Dark only. Colours:
    *   accent `#7FE3F7`, second accent `#8FA2FF`
    *   hold `#FFC56B`, up `#63DFA5`, down `#FF7F8A`
    *   text `#EAF1F7`, muted `#92A4B6`
    *   sidebar `#0A0D14`
*   **Motion.** A. Settle everywhere: each part fades up from 10 px below, about 70 ms apart and
    0.5 s each; leaving fades and lifts 8 px in about 0.24 s. Nothing moves under the Mac's Reduce
    motion setting.
*   **Copy.** Sentence case, plain words, no all-caps labels. The spec's wording is used verbatim
    where it gives it.
*   **Files this plan must not touch.** The "Build Phase 0" session has uncommitted work in these,
    in the main checkout:
    *   `engine/src/tearsheet/pipeline.py`, `cli.py`, `grading.py`, `golden.py`, `normalize.py`,
        `sources.py`, `data/sec.py`, `__init__.py`
    *   `engine/src/tearsheet/methodology/aliases.yaml`
    *   their tests, `evals/golden/`
    *   `engine/tests/fixtures/runs/tearsheet.sqlite`

    Read them; never edit them.
*   **Commits.** Every commit message ends with:
    `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`
    Never push, and never merge into `main`.
*   **Checks.** These must pass at the end of every task that touches their side:
    *   `cd engine && uv run pytest`
    *   `cd app && npm run typecheck && npm test`

## Review Focus

1.  **Old reports with lines missing.** A report saved before a code-written line existed, or with
    a line in an unexpected format, still renders. Each missing piece shows "not stored for this
    report", and nothing raises. *Tested in Task 1 (`test_missing_lines_give_none`) and Task 4
    (`test_old_report_renders_with_gaps`).*
2.  **Look-up input.** Typing `brk-b`, `BRK.B`, ` nvda `, `Google` or `alphabet` finds the right
    company. A name outside the S&P 500 returns an empty list, not an error. *Tested in Task 2
    (`test_search_*`).*
3.  **Network failures during key checks.** A rejected key, and Massive or FRED being
    unreachable, give two different messages. A rejected key is never saved. *Tested in Task 5
    (`test_check_key_*`).*
4.  **Starting a second job.** A safety check while a report runs, a second safety check, or a
    full-history download while a report runs each return a clear error code, and none of them
    corrupts the running job. *Tested in Task 5 (`test_safety_check_refuses_while_busy`) and
    Task 3 (`test_fetch_history_refuses_while_running`).*
5.  **Divider limits.** In a window too narrow for both the chart's 360 px and the text's 340 px,
    the divider goes straight to Full and never lays out a negative width. *Tested in Task 12
    (`snapWidth` cases).*

### Task 1: Numbers from any stored report

The numbers column reads the code-written lines every report already has, plus stored tables.
Nothing new is written at save time, so old reports fill in too.

**Files:**
- Create: `engine/src/tearsheet/report_numbers.py`
- Test: `engine/tests/test_report_numbers.py`

**Interfaces:**
- Produces:
    - `parse_code_lines(report: dict) -> dict`. Every key is always present, with a value or
      `None`:
        - `rating: {"call": str, "capped": bool, "uncertainty": str|None}`
        - `score: {"percentile": int}`
        - `range: {"bear": float, "base": float, "bull": float}`
        - `price: {"value": float, "date": str}`
        - `estimate: {"value": float, "gap_percentile": int|None}`
        - `triggers: {"buy": float|None, "sell": float|None, "buy_text": str, "sell_text": str}`
        - `factors: [{"name": str, "percentile": int, "weight": float}]`
        - `methods: [{"method": str, "value": float}]`
        - `returns_12m: {"company": float, "peers": float, "spy": float}`
        - `peer_ratings: {"Buy": int, "Hold": int, "Sell": int}`
        - `economy: [{"series": str, "label": str, "value": str, "date": str}]`

        - `weekly: [{"date": "YYYY-MM-DD", "close": float}]`

        - `red_flags: [str]`
    - `numbers_for(conn, report: dict, run_id: str, cik: int) -> dict`, which merges the two.

### Task 5: Setup in the engine: key checks, the safety check and setup settings

**Files:**
- Create: `engine/src/tearsheet/setup_checks.py`
- Modify: `protocol.py`, `server.py` and `config.py`
- Test: `engine/tests/test_setup_checks.py`

**Interfaces:**
- Produces:
    - `async check_key(http, service: Literal["massive","fred"], key: str) -> str`. It makes one
      call and returns the proof line exactly:
        - Massive: `Works. SPY closed at $735.59 on Nov 5.` (SPY's latest close, with the date
          formatted as `Mon D`)
        - FRED: `Works. The 10-year Treasury yield is 4.9%.` (the latest DGS10 value)
    - It raises `EngineError("KEY_REJECTED", ...)` on 401 or 403, or when the service's own
      error says the key is invalid. It raises `EngineError("SERVICE_UNREACHABLE", ...)` on
      connection errors, timeouts and 5xx responses.
    - The RPC method `check_key(CheckKeyParams{service, key})` calls `config.set_key` **only after**
      the check passes, and returns `{"proof": str}`.
    - The RPC method `run_safety_check(SafetyParams{tool: "claude"|"codex"})` returns
      `{"started": True}` at once, then runs `ai.lockdown.run_check(connector, form="full",
      progress=cb)` as a job. Each call emits
      `safety_progress{tool, n: int, total: 25, name: str, ok: bool}`, and the end emits
      `safety_done{tool, passed: bool, reason: str|None}`.
    - The safety check refuses with `RUN_IN_PROGRESS` while a report runs, and with
      `SAFETY_CHECK_RUNNING` while another check runs. A report started during a check refuses
      with `SAFETY_CHECK_RUNNING`.
    - New settings in `config.SETTINGS` and the `SetSettingParams` literal: `setup_done` ("0" or
      "1") and `fred_skipped` ("0" or "1"). `get_settings` returns both, as booleans.
